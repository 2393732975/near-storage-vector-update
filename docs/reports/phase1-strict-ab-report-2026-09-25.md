# 阶段 1 Compute/OSD 严格 A/B 报告（2026-09-25）

## 结论

阶段 1 的性能与正确性基线已建立。四个数据集、两条距离路径各完成三次独立
重导入，共 24/24 轮、61,318 次更新；所有轮次均为 `failed_updates=0`，结构检查
`status=pass`、`errors=0`，抽样图边语义胜率为 0.992233–1.000000。

当前 OSD 卸载没有形成稳定性能收益：平均延迟相对 compute 的变化范围为
-2.16%–+2.42%，且三轮 95% 置信区间明显重叠。主要瓶颈不是距离算术，而是每次
更新约 417–591 个距离批次、每批仅 1.009–1.114 个候选所造成的细粒度 RPC、排队
和 query 重复传输。因此下一实现阶段应优先聚合 frontier 和按对象批量算距。

## 阶段判定与后续动作

- **正确性与可观测性：通过。** 零失败、结构一致性和语义局部性门禁全部通过。
- **可比较基线：通过。** 固定提交、二进制、数据、池布局与三次独立重复均已记录。
- **OSD 性能优化目标：未达到。** 当前差异小且方向不一致，不能宣称卸载带来收益。
- **严格质量等价：待补充。** Text2Image10M 需执行共同 query 前缀复核。
- **下一实现优先级：** 单次更新内按对象聚合 frontier/候选，使 candidates/batch
  至少达到 8、distance batches/update 降到 50 以下，并减少至少 80% query bytes。

Recall 是更新提交前 level-0 搜索相对原始 base ground truth 的静态指标，不是更新
后动态数据集的精确 Recall。导入会预热缓存，报告结果也不能解释为冷缓存性能。
