## 故障发现与修正

修正前的 GIST 诊断轮曾出现 15 次 45 s timeout，并留下 7 个 active orphan；取消
无超时运行后又发现 1 个 active orphan 和计数不一致。根因是同步 RADOS 响应存在
不确定完成边界：直接报告 timeout 会遗留部分提交，取消 timeout 又可能永久等待。

提交 `514cd94` 为 ID 预留、finalize 和 edge patch 增加 `update_id` 去重，使向量、
邻接和 label 更新可安全重放；提交 `c0d9c25` 改为从 meta OMAP 读取已持久化的
reservation。正式结果只使用修正后的完整运行，两个失败诊断目录不纳入性能数据。

## 集群收尾

验收后已用白名单清理脚本删除全部 `nsvu_*` 池。集群最终为 5 OSD `up/in`、33 PG
`active+clean`。Ceph 仍报告 5 个 OSD 的 BlueStore slow-op 历史统计和既有
`devicehealth` 磁盘 I/O 错误；这些告警未被清除或屏蔽，物理空间回收由 BlueStore
异步完成。
