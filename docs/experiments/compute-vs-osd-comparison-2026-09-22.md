# Compute-node 与 OSD/CLS 实验对比报告（2026-09-22）

## 对比范围

本报告比较两次已完成实验中的相同 `avg_update_latency_ms`、吞吐和阶段打点：

- Compute-node 背景数据移动实验：`results/ppt-background-20260921T082253Z/compute/`，代码提交 `9860c50`；
- OSD/CLS baseline：`results/ppt-baseline-20260917T101500Z/osd/`，实验报告记录的代码提交为 `36a9a1e`。

两次实验均使用 GIST1M、Text2Image10M、Deep100M、SIFT100M，更新时间窗 300 秒，`UPDATE_PARALLELISM=4`，并为每个数据集重新导入 base、重建独立的单副本 `nsvu_*` 池。原始 JSON 含机器本地数据，不纳入 Git。

## 结论

Compute-node 在 GIST1M、Text2Image10M 和 Deep100M 上平均更新时间低 24.3%–38.3%，吞吐高 16.2%–36.4%；OSD/CLS 在 SIFT100M 上平均更新时间低 4.4%，吞吐高 12.5%。OSD/CLS 完全消除了候选向量回传，但当前细粒度 CLS 调用的 RTT/OSD 排队、payload 读取和图搜索控制开销抵消了这一收益。

这不表示数据移动不重要：Compute 路径的距离阶段中，98.15%–99.78% 时间仍用于向量 RPC，纯本地算距仅占 0.18%–1.81%。结果说明“下沉距离计算”是必要条件，但尚不足以形成稳定的端到端性能优势。

## 主更新路径累计工作时间占比

分母是各 worker 的不重叠主路径累计工作时间，而不是墙钟 `graph_seconds`；因此适用于并发度 4，且各主阶段合计约为 100%。

| 数据集 | Compute：距离 / meta / patch / 搜索控制 | OSD：距离 / meta / patch / 搜索控制 |
| --- | ---: | ---: |
| GIST1M | 39.53% / 44.87% / 11.28% / 3.44% | 36.75% / 21.07% / 13.21% / 27.96% |
| Text2Image10M | 41.32% / 41.09% / 13.16% / 3.29% | 30.53% / 38.09% / 8.73% / 22.00% |
| Deep100M | 51.62% / 30.08% / 14.14% / 3.43% | 33.76% / 34.15% / 9.58% / 21.86% |
| SIFT100M | 57.87% / 24.83% / 12.27% / 4.18% | 40.76% / 20.40% / 11.09% / 27.02% |

OSD 路径的“搜索控制”明显增大，是因为 `full_graph_search_exclusive_seconds` 包含 Coordinator 候选维护、邻接读取及扣除远端算距后的控制路径；它不等同于纯 CPU 图算法时间。

## 距离阶段内部拆分

| 数据集 | Compute 向量 RPC | Compute 本地算距 | OSD RTT/排队 | OSD VectorRef | OSD payload | OSD 纯算距 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| GIST1M | 98.15% | 1.81% | 71.75% | 2.76% | 24.01% | 0.81% |
| Text2Image10M | 99.74% | 0.21% | 59.09% | 5.61% | 34.60% | 0.21% |
| Deep100M | 99.76% | 0.19% | 55.83% | 7.99% | 35.67% | 0.09% |
| SIFT100M | 99.78% | 0.18% | 56.21% | 8.50% | 34.71% | 0.13% |

Compute 的瓶颈是完整候选向量 RPC；OSD/CLS 的瓶颈则转移为调用往返/排队和 payload 读取。两条路径中的纯距离算术都不是主要成本。

## 有效性限制

- 两组数据来自 9 月 17 日和 9 月 21 日，不是同一轮交错执行的严格 A/B；后一次实验结束后集群报告五个 OSD 的 BlueStore slow-op，而所有 PG 仍为 `active+clean`。
- OSD 实验启用了 `distance_split_probe`，每批距离请求附加 `timed_noop` 探针；其数据适合瓶颈剖析，不代表移除探针后的生产性能。
- 每组有 5–11 次失败更新。失败归零并在相同集群状态下完成重复试验前，不应把平均延迟差异作为最终论文结论。
- 两轮末批并发操作会使实际 `graph_seconds` 偏离 300 秒；吞吐使用 JSON 已记录的 `vectors_processed / graph_seconds`，未强制按 300 秒重算。

下一轮应在同一提交、相同池落点和稳定健康状态下使用 `MODES="compute osd"` 连续运行，并至少重复三次报告均值、标准差和 P99。
